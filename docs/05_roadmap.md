# 開発ロードマップ

「小さく作って動作確認を繰り返す」方針に基づき、MVPを7つのフェーズに分割する。
各フェーズの終わりで動くものを確認してから次に進む。

## Phase 0：設計承認 ✅完了

- [要件定義](01_requirements.md) / [システム構成](02_architecture.md) /
  [DB設計](03_database_design.md) / [画面設計](04_screen_design.md) のレビュー
- 内容に問題なければ承認 → Phase 1へ

## Phase 1：環境構築 ✅完了

- GitHub Private Repositoryの作成
- frontend（React+TS+Vite）／backend（Node+Express+TS）の雛形作成
- Supabaseプロジェクト作成、DB接続確認
- 「Hello World」レベルでフロント⇔バックエンド⇔DBの疎通確認

**確認ポイント**：ブラウザから叩いたAPIがDBの値を返せること

## Phase 2：人生理念・ロードマップ機能 ✅完了

- `life_philosophy` / `visions` / `goals` / `categories` のCRUD API
- 人生理念画面、ロードマップ画面（ツリー表示・編集）の実装

**確認ポイント**：理念を書き換えても履歴が残ること、目標の階層が正しく表示されること

## Phase 3：今日のタスク機能 ✅完了

- `tasks` のCRUD API
- 今日のタスク画面（時間割表示、チェック操作）
- ダッシュボード画面の初期版

**確認ポイント**：ルーティンに沿ったタスクが表示・完了操作できること

## Phase 4：Googleカレンダー同期 ✅完了

- Google OAuth連携（ログイン）
- カレンダー読み取り → `google_calendar_links`との突き合わせ
- 書き込みは実装しない（自動での一括同期・更新はPhase 8以降）。ただし、Phase 6で
  「ユーザーが個別に承認した1件だけをカレンダーに書き込む」処理を追加するため、
  そのための最小限のAPIラッパー（イベント作成・更新の関数）はここで用意しておく

**確認ポイント**：実際のGoogleカレンダーの当日予定が今日のタスク画面に反映されること

## Phase 5：毎日の振り返り機能 ✅完了

- `reflections` のCRUD API
- 振り返り入力画面

**確認ポイント**：夜に振り返りを保存でき、翌朝ダッシュボードに表示されること

## Phase 6：AIによる改善提案機能 ✅完了

AIをプロダクトの中核機能として実装する（詳細は[要件定義 8章](01_requirements.md#8-ai連携プロダクトの中核機能)、
[システム構成 7章](02_architecture.md#7-ai連携アーキテクチャ)を参照）。

- `AIProvider`インターフェースと`ClaudeProvider`/`GeminiProvider`の2実装、プロンプトのテンプレート
  分離（`backend/src/ai/`）。既定は**Gemini**（無料枠、`AI_PROVIDER=gemini`）
- 振り返り保存をトリガーに、AIで以下を生成し`ai_suggestions`へ保存
  - 今日の要約 / 課題 / 原因の仮説 / 明日の改善案（最大3件） / 継続すべきこと
- カレンダー変更案（最大2件）を生成し`ai_calendar_proposals`へ保存（提案のみ、まだ反映しない）。
  大きな課題がない日は無理に提案しない（0件のことがある、これは意図した挙動）
- 振り返り画面：要約・改善案の表示、カレンダー変更案ごとに「承認する」「却下する」ボタン
- ユーザーが承認したカレンダー変更案のみ実際にGoogleカレンダーへ反映（`applied_at`を記録）。
  却下した場合も結果を記録する

実カレンダーで承認→反映／却下→未反映の両方を確認済み。

**MVP外（Phase 8以降）**：週間目標と日々の行動のズレ検知、長期目標からの逸脱警告、
過去傾向の分析、タスクへの自動分解、ロードマップの自動再構築。

## Phase 8以降（運用しながらの拡張候補）

優先度は運用してみてから決める想定だが、現時点での候補：

- 振り返り履歴・分析画面（グラフ、傾向分析）
- AIによる長期分析（週間目標とのズレ検知、長期目標からの逸脱警告、過去傾向の分析）
- AIによるタスクの自動分解、ロードマップの自動再構築（提案ベースを維持しつつ精度向上）
- Googleカレンダーの自動一括同期（現状は個別承認したものだけを反映）
- 継続日数（ストリーク）管理、`habits`テーブルの追加
- OpenAIなど他AIモデルへの対応（`AIProvider`実装の追加。Claude/Geminiは対応済み）
- PWA化・モバイル最適化

## 進め方の原則

- 各フェーズ完了時に動作確認し、認識合わせをしてから次へ進む
- 仕様変更が必要になった場合は、変更理由を説明した上で提案する（勝手に変更しない）
- 実装は一度に広げすぎず、小さいPRを積み重ねる
