# 開発ロードマップ

「小さく作って動作確認を繰り返す」方針に基づき、MVPを7つのフェーズに分割する。
各フェーズの終わりで動くものを確認してから次に進む。

## Phase 0：設計承認（現在地）

- [要件定義](01_requirements.md) / [システム構成](02_architecture.md) /
  [DB設計](03_database_design.md) / [画面設計](04_screen_design.md) のレビュー
- 内容に問題なければ承認 → Phase 1へ

## Phase 1：環境構築

- GitHub Private Repositoryの作成
- frontend（React+TS+Vite）／backend（Node+Express+TS）の雛形作成
- Supabaseプロジェクト作成、DB接続確認
- 「Hello World」レベルでフロント⇔バックエンド⇔DBの疎通確認

**確認ポイント**：ブラウザから叩いたAPIがDBの値を返せること

## Phase 2：人生理念・ロードマップ機能

- `life_philosophy` / `visions` / `goals` / `categories` のCRUD API
- 人生理念画面、ロードマップ画面（ツリー表示・編集）の実装

**確認ポイント**：理念を書き換えても履歴が残ること、目標の階層が正しく表示されること

## Phase 3：今日のタスク機能

- `tasks` のCRUD API
- 今日のタスク画面（時間割表示、チェック操作）
- ダッシュボード画面の初期版

**確認ポイント**：ルーティンに沿ったタスクが表示・完了操作できること

## Phase 4：Googleカレンダー同期

- Google OAuth連携（ログイン）
- カレンダー読み取り → `google_calendar_links`との突き合わせ
- （MVPは読み取り中心。書き込み反映はPhase 8以降で段階的に有効化）

**確認ポイント**：実際のGoogleカレンダーの当日予定が今日のタスク画面に反映されること

## Phase 5：毎日の振り返り機能

- `reflections` のCRUD API
- 振り返り入力画面

**確認ポイント**：夜に振り返りを保存でき、翌朝ダッシュボードに表示されること

## Phase 6：AIによる改善提案機能

- Claude APIと連携し、振り返り内容から`ai_suggestions`を生成
- 提案の表示・採否記録

**確認ポイント**：振り返り保存直後にAI提案が表示され、内容が的外れでないこと
（プロンプトはここで実際の使用感を見ながら調整する）

## Phase 7：MVP統合・運用開始

- Phase 1〜6の結合テスト（1日通しての実運用フロー確認）
- README・仕様書の最終更新
- 本番デプロイ（Vercel / Render）

ここで一度運用を開始する。

## Phase 8以降（運用しながらの拡張候補）

優先度は運用してみてから決める想定だが、現時点での候補：

- 振り返り履歴・分析画面（グラフ、傾向分析）
- ロードマップの自動更新（AI提案の自動反映）
- Googleカレンダーへの書き込み同期（自動でイベント作成・更新）
- 継続日数（ストリーク）管理、`habits`テーブルの追加
- PWA化・モバイル最適化

## 進め方の原則

- 各フェーズ完了時に動作確認し、認識合わせをしてから次へ進む
- 仕様変更が必要になった場合は、変更理由を説明した上で提案する（勝手に変更しない）
- 実装は一度に広げすぎず、小さいPRを積み重ねる
