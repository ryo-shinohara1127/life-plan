# 画面設計書

## 1. 画面一覧

| # | 画面名 | 目的 |
|---|---|---|
| 1 | ダッシュボード（ホーム） | 今日の全体像を1画面で把握する |
| 2 | 人生理念 | 理念の閲覧・編集・変更履歴 |
| 3 | ロードマップ | 人物像〜週目標の階層をツリーで見る・編集する |
| 4 | 今日のタスク | 当日タスクの実行・チェック |
| 5 | 振り返り入力 | 夜に振り返りを記録する |
| 6 | 振り返り履歴・分析 | 過去の振り返りとAI提案を振り返る |
| 7 | 設定 | Googleカレンダー連携、テーマ設定 |

## 2. 画面遷移図

```
                ┌──────────────┐
                │ ダッシュボード │◀───────────────┐
                └──────┬───────┘                │
      ┌─────────┬───────┼────────┬─────────┐    │
      ▼         ▼        ▼        ▼         ▼    │
   人生理念  ロードマップ 今日のタスク 振り返り入力  設定  │
                                    │              │
                                    ▼              │
                              振り返り履歴・分析 ────┘
```

すべての画面はダッシュボードを起点に行き来できるグローバルナビゲーションを想定。

## 3. 各画面の詳細

### 3.1 ダッシュボード（ホーム）

- 上部：人生理念の一文（クリックで理念ページへ）
- 中央：今日のタスク一覧（チェックボックス付き、完了率バー）
- 右側：直近の振り返りサマリー（気分・集中度の推移ミニグラフ）
- 下部：直近のAI改善提案（未反映のものがあれば強調表示）

> 設計意図：「理念→今日のタスク→振り返り」の一直線を1画面に凝縮し、
> 毎朝ここを見るだけで今日やることと自分の軸を同時に確認できるようにする。

### 3.2 人生理念

- 現在の理念を大きく表示
- 「編集する」ボタン → 新しい理念をINSERT（`life_philosophy`はInsert-onlyのため上書きしない）
- 過去の理念の変遷を時系列リストで表示

### 3.3 ロードマップ

- 階層ツリー表示：3〜5年後の人物像 → 1年目標 → 3か月目標 → 月目標 → 週目標
- 各ノードはテーマ（AI/筋トレ/読書など）で色分け
- ノードクリックで詳細編集（タイトル・説明・期間・ステータス）
- 「柱」テーマ（AI/筋トレ/読書）のみここに階層目標を持つ想定（`categories.type = pillar`）

> 設計意図：写真・コーヒー・歌のような`daily_touch`テーマはロードマップに階層目標を作らず、
> 今日のタスク側で「継続できているか」だけを見る設計にする。理由は要件定義にある通り、
> これらは「深く追求する目標」ではなく「毎日少し触れる習慣」だから。

### 3.4 今日のタスク

- 時間割形式（ルーティンの時間帯順）でタスクを並べる
- 各タスクにチェックボックス、ステータス（未着手／進行中／完了／スキップ）
- Googleカレンダーとの同期状況アイコン（同期済み／未同期／エラー）
- 前日夜に「明日の自由時間に追加する予定」を入力できる簡易フォーム

### 3.5 振り返り入力

- フォーム項目：できたこと／できなかったこと／理由／今日の学び／改善案／気分（5段階）／
  集中度（5段階）／睡眠時間
- 保存すると、その場でAI改善提案をリクエストし、結果を下に表示
- 提案内容に対して「反映する／却下する」を選べる（MVPでは反映＝手動でロードマップ/タスクを更新）

### 3.6 振り返り履歴・分析

- 日付ごとの振り返り一覧（フィルタ：期間、テーマ）
- 気分・集中度・睡眠時間の推移グラフ
- 過去のAI提案とその採否履歴

### 3.7 設定

- Googleアカウント連携状態（連携する／解除する）
- 同期対象カレンダーの選択
- テーマ（categories）の優先順位・柱／daily_touch区分の編集

## 4. UI方針

- 情報量が多いため、ダッシュボード以外は「1画面1目的」を徹底し情報を詰め込みすぎない
- 色分けはテーマ（AI/筋トレ/読書/写真/コーヒー/歌）で統一し、どの画面でも同じテーマ色を使う
  ことで直感的に認識できるようにする
- スマホからも見られるようレスポンシブ対応を前提とする（PWA化は運用後フェーズで検討）
